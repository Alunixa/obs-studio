# NVENC API 多版本自动兼容

版本：`32.2.2-alunixa.20261017.1`，Windows x64 预发布，喵~

## 修复内容

- 修复以 API 13.0 编译的插件和能力探测器拒绝只支持 API 12.1/12.2 的驱动，喵~
- 同一 ZIP 内的一个 NVENC 插件包含 12.1、12.2、13.0 三套隔离的编码后端，不需要用户选择不同安装包，喵~
- 启动时调用 `NvEncodeAPIGetMaxSupportedVersion`，自动选择驱动支持的最高已编译版本；插件和独立能力探测器使用相同规则，并校验两者选择一致，喵~
- 每套后端使用对应版本的完整头文件、原生结构体布局和版本号；不是只把 13.0 的结构体改写成低版本标记，喵~
- 保留 H.264/HEVC/AV1、纹理编码和 CUDA 路径、既有编码器 ID、用户配置及单文件回放缓存修复；不会更新驱动或改写用户的码率和色彩格式，喵~

## 自动选择

| 驱动报告的最大 API | 自动使用 |
| --- | --- |
| 13.0 及以上 | 13.0 |
| 12.2 至低于 13.0 | 12.2 |
| 12.1 至低于 12.2 | 12.1 |
| 低于 12.1，或 NVENC 库不可用 | 不注册 NVENC 编码器，保留其他编码器 |

实际编解码格式和功能仍取决于 GPU 能力；例如旧 GPU 不会因为 API 选择而获得 AV1，喵~

UHQ 等 12.2+ 功能和 H.264 high10、四路拆分等 13.0 功能只在对应后端开放；若现有配置明确要求当前 API 不支持的功能，会报错而非静默降低配置，喵~

无损模式会按既有行为使用无损调优，I444 会使用对应 4:4:4 profile；这些模式下不参与输出的旧调优/profile 配置值不会造成错误拒绝，喵~

## 构建与验证

- 构建时按 SHA-256 校验固定的 NVIDIA/FFnvcodec 头文件 `n12.1.14.0`、`n12.2.72.0`、`n13.0.19.0`，缓存位于构建目录，保留上游许可，喵~
- GitHub Actions 完整编译并链接三套真实编码后端和三套探测后端，通过回归和关键插件依赖加载验证后发布 ZIP，喵~
- 无显卡模拟测试覆盖精确版本与未来版本选择、旧版本拒绝、结构体修订、函数表清零、CUDA/D3D11 会话参数、preset 嵌套版本、初始化错误传播和拆分编码禁用值，喵~
- 同时保留并运行回放缓存生命周期、失败保存有界回收、异常退出清理及 muxer 故障回归，喵~
- 本轮没有进行旧版驱动真实 GPU 编码测试，也不宣称修复 VLC 的播放器花屏或字幕卡死，喵~

独立运行不依赖显卡的兼容性回归，喵~

```powershell
cmake -S test/nvenc-compat -B build-nvenc-api-tests
cmake --build build-nvenc-api-tests --config Release
ctest --test-dir build-nvenc-api-tests -C Release --output-on-failure
```

运行时日志会显示已选 API 和驱动最大 API；源码提交、Actions 运行及 ZIP 校验和以发布页下方的构建证据为准，喵~
